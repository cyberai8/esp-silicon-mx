# 数字人中文口型（音素/视素）素材制作说明

**文档用途**：供产品、设计制作口型素材；开发与服务端按同一套 ID 对接。  
**范围**：仅「说话口型 / Viseme」，不含情绪表情、不含能量档口型。  
**角色**：以现有办公室男性数字人为准（360×360，正面半身）。  
**版本**：v1.2（ü 与 er 分拆为两张）

---

## 1. 背景与目标

设备播放 TTS 语音时，服务端同步下发**带时间戳的视素（Viseme）序列**，端侧按时间切换对应嘴形图，实现中文对口型。

- 制作单位是 **Viseme（视素）**，不是「每个拼音各做一张」。
- 多个中文音素会共用同一嘴形（例如 b/p/m 都是闭唇）。
- 本版确定制作 **11 张主口型**（ID 0～10），可覆盖普通话日常对话。**ü 与 er 分两张，不可合并。**

---

## 2. 交付物一览（设计师只需做这些）

| 序号 | 文件名（请严格按此命名） | 口型名称 | 一句话要求 |
|---:|:---|:---|:---|
| 0 | `viseme_00_rest.png` | 静音/放松 | 自然闭口，平静，可作为其余口型的对齐基准 |
| 1 | `viseme_01_bmp.png` | 双唇闭合 | 双唇抿紧（比微笑更用力），用于 b/p/m |
| 2 | `viseme_02_f.png` | 唇齿 | 上齿轻咬下唇，用于 f |
| 3 | `viseme_03_sz.png` | 齿缝微张 | 上下齿接近、缝很小，可微露齿，用于 z/c/s 等 |
| 4 | `viseme_04_a.png` | 开口 a | 嘴巴垂直方向明显张开，用于 a 及含 a 的韵母 |
| 5 | `viseme_05_e.png` | 扁中开 e | 中等张开、嘴形偏扁、露齿，用于 e 类 |
| 6 | `viseme_06_i.png` | 扁拉 i | 嘴角向两侧拉开，开口不大，用于 i、j/q/x |
| 7 | `viseme_07_o.png` | 圆唇 o | 嘴唇收圆、中等开口（禁止大笑露齿），用于 o |
| 8 | `viseme_08_u.png` | 紧圆 u | 嘴唇撮成小圆孔，用于 u、w 等 |

> **注意：**  
> - **ü ≠ er**：必须两张图（ID9 / ID10）。  
> - **ü ≠ üe**：üe（月、略）是滑音，设计**不必**再画一张；说话时由程序按 **撮口(9)→扁中开 e(5)** 切换。üan 同理用 **9→4(a)**。

**合计：11 张静态 PNG（主交付）。**

## 2.1 静态还是动画？怎么说才流畅？

### 结论（给老板 / 设计）

| 问题 | 答案 |
|:---|:---|
| 口型素材做什么格式？ | **以静态 PNG 关键帧为主**（每个 Viseme 一张「最典型嘴形」） |
| 要不要做长 GIF 动画？ | **不要**。长 GIF 里混多种嘴形，无法跟音素时间轴对齐 |
| 流畅靠谁？ | **主要靠程序过渡**（交叉淡入 + 提前量），不是靠每张做成动画 |
| 可选加分项 | 每个 Viseme 额外提供 **2～3 帧微动**（同一嘴形轻微开合），用于长音时「活一点」 |

### 为什么主交付是静态图？

音素对口型的本质是：

```text
某一时刻音频对应某一个嘴形 ID → 显示那一张图
下一时刻换成另一个 ID → 再切图
```

因此设计交付的是 **11 个「口型关键姿势」**，不是 10 段「自己在动的说话动画」。  
若做成整段说话 GIF，程序无法在「嘛」的 m 上精确停在闭唇。

### 上板格式（研发转码，设计可不做）

| 阶段 | 格式 |
|:---|:---|
| 设计交稿 | `viseme_XX_*.png`（360×360） |
| 设备运行 | 可转为 EAF/SJPG；**仍是「每 ID 一套短资源」**，不是长循环说话片 |

### 流畅感怎么来（研发实现；设计需配合对齐）

人眼觉得「顺」，靠下面几条叠加：

1. **交叉过渡（最重要）**  
   从口型 A 切到 B 时，用约 **30～80ms** 做透明度交叉（A 淡出、B 淡入），禁止硬切闪一下。

2. **提前量 / 滞后（协同发音）**  
   下一个嘴形提前 **20～60ms** 开始露头；上一个嘴形不要瞬间归零。  
   例：「嘛」的 m（闭唇）要够清楚，再过渡到 a（大开）。

3. **刷新率**  
   口型更新目标 **≥15～20 次/秒**；闭唇类（b/p/m）往往只有几十毫秒，刷新太低会「闭不上」。

4. **设计侧对齐**  
   10 张图头位锁定、仅嘴部差异大，过渡时才不会出现「整脸在跳」。

5. **可选：同 ID 微动帧（P1 加分）**  
   若某音素持续较长（如拉长的 a），可在同一 ID 下准备 2～3 张开口略有差异的静帧，程序在该 ID 时间段内轻微来回切，避免「嘴冻住」。  
   - 命名示例：`viseme_04_a.png`（主）、`viseme_04_a_b.png`、`viseme_04_a_c.png`  
   - **第一期可不做**；有主静帧即可上线。

### 设计交付优先级

| 优先级 | 交付 | 说明 |
|:---|:---|:---|
| **P0 必须** | 每 ID **1 张**静态主图 | 本期唯一硬性要求 |
| P1 可选 | 每 ID 再加 2 张微动静帧 | 提升长音自然度 |
| 不做 | 整段说话长 GIF / 多种嘴形混在一个文件里 | 无法按音素驱动 |

## 3. 制作规范（务必遵守）

### 3.1 画布与对齐

| 项 | 要求 |
|:---|:---|
| 尺寸 | **360 × 360** 像素 |
| 构图 | 正面半身，与现有角色一致（办公室背景可保留） |
| 对齐 | 以 `viseme_00_rest.png` 为基准；**头、眼、肩位置锁定**，各图之间只允许嘴、下颌、脸颊随口型变化 |
| 格式 | **静态 PNG**，sRGB；可与现稿同样实底（不必透明） |
| 命名 | 必须使用第 2 节文件名，便于程序加载 |

### 3.2 画法注意

1. 角色有**下巴胡须**，张嘴/闭嘴时胡须与下颌要一起动，勿只改嘴唇线。  
2. **不要**把「开心大笑」当成 a 或 o；大笑属于情绪，不在本清单。  
3. `viseme_01_bmp` 必须是真正的闭唇（说话里的「嘛/吗」的 m），不能只是微笑闭口。  
4. `viseme_07_o` / `viseme_08_u` 必须是**圆唇**，不能是横向咧嘴露齿。  
5. 每张图是**静止关键帧**（该音素最典型的嘴形），不要提交一整段混合多种嘴形的长 GIF 作为终稿。  
6. 流畅不靠把单张画成动画，靠 **10 张之间差异合理 + 程序淡入淡出**；静帧之间嘴形跨度不要极端到无法过渡（例如从全闭直接到极端大开中间最好在套件里有中等开口可路过）。

### 3.3 验收标准（设计自检）

- [ ] 11 张文件名、尺寸正确  
- [ ] 叠在一起看，五官位置对齐，无整头漂移  
- [ ] 0 与 1 能区分：1 更「抿」  
- [ ] 2 能明确看出上齿咬下唇  
- [ ] 4 开口明显大于 5、6  
- [ ] 7、8 为圆唇；8 的开口明显小于 7  
- [ ] 9 为撮口 ü；10 为儿化，**二者口形明显不同**（10 不撮口）  
- [ ] 无人脸裁切、无水印、无多余 UI 文字

## 4. 音素对照表（给设计理解「这张嘴在说什么」）

> 开发/服务端按此表把拼音映射到 ID；设计无需逐字制作，只需保证 10 张嘴形区分清晰。

### 4.1 声母 → 口型

| 声母 | 使用口型 | ID |
|:---|:---|:---:|
| b、p、m | 双唇闭合 | 1 |
| f | 唇齿 | 2 |
| z、c、s | 齿缝微张 | 3 |
| zh、ch、sh、r | 本版暂同齿缝（3） | 3 |
| j、q、x | 同扁拉 i | 6 |
| d、t、n、l | 嘴形弱，过渡常用 3 或 5 | 3/5 |
| g、k、h | 一带而过，常用 5 | 5 |
| y | 同 i | 6 |
| w | 同 u | 8 |
| 零声母 | 跟韵母走 | — |

### 4.2 韵母 → 口型

| 韵母 | 使用口型 | ID |
|:---|:---|:---:|
| a、ai、ao、an、ang | 开口 a（ai/ao 精细时可再滑向 i/o） | 4 |
| o、uo | 圆唇 o | 7 |
| e、ê、ei、en、eng | 扁中开 e | 5 |
| i、ia、ian、iang、ie、in、ing | 扁拉 i | 6 |
| u、ua、uai、uan、uang、ui、un、ou、ong | 紧圆 u | 8 |
| ü、ün | 撮口 ü | 9 |
| üe | 滑音：撮口→e | 9→5（不新做图） |
| üan | 滑音：撮口→a | 9→4（不新做图） |
| er | 儿化 | 10 |
| 静音/停顿 | 静音放松 | 0 |

## 5. 示例：这句话会怎么切口型

**例句：你在干嘛**

| 字 | 拼音 | 口型顺序（简写） | 用到的素材 |
|:---|:---|:---|:---|
| 你 | nǐ | 微张 → **扁拉 i** | ID 3 → **6** |
| 在 | zài | 齿缝 → **开口 a** → 扁 i | **3 → 4 → 6** |
| 干 | gàn | 过渡 → **开口 a** | 5 → **4** |
| 嘛 | ma | **双唇闭** → **开口 a** | **1 → 4** |
| 句末 | — | 回静音 | **0** |

设计验收时可用此句自测：能否看出「嘛」先闭嘴再张嘴。

## 6. 服务端 / 设备如何使用（给老板与研发对齐）

1. TTS 合成音频的同时，生成视素时间轴，例如：  
   `[{ "id": 6, "t0_ms": 40, "t1_ms": 180 }, ...]`  
2. 设备按播放时间取当前 `id`，显示对应 `viseme_XX_*.png`（或转好的 EAF）。  
3. 相邻口型做短时过渡（约 20～60ms），避免硬切。  
4. **本清单不包含情绪图**；情绪由其它资源管理，与口型分层或分时段使用。
